# Queue Item Dialog Isolation - Manual Test

## 问题描述
在队列中打开不同 QueueItem 的 Transcription View 时，Run Details 正确显示了对应项的信息，但 Workspace 标签页却显示了上一个项的内容。

## 修复内容
1. 在 `queue_view.py` 的 `_on_open_view()` 方法中，添加了在打开新项之前调用 `clear_content()` 的逻辑
2. 增强了 `transcription_view_dialog.py` 的 `clear_content()` 方法，确保完全清除所有状态：
   - 清除转录状态（路径、视图、可编辑转录等）
   - 停止并清除媒体播放器
   - 清除所有 UI 元素（使用 blockSignals 防止触发变更处理器）
   - 禁用所有控件

## 手动测试步骤

### 准备工作
1. 启动 FlowScribe GUI
2. 切换到 Queue 视图
3. 添加至少 2 个不同的转录任务到队列（可以是本地文件或 URL）
4. 运行队列，等待至少 2 个任务完成

### 测试场景 1：在已完成的项之间切换
1. 在队列列表中，勾选第一个已完成的项
2. 点击 "Open View" 按钮
3. 在打开的对话框中：
   - 检查 "Run Details" 标签页，确认显示的是第一个项的运行日志
   - 切换到 "Workspace" 标签页，确认显示的是第一个项的转录内容
   - 记下转录片段的内容（例如第一句话）
4. 关闭对话框
5. 取消勾选第一个项，勾选第二个已完成的项
6. 再次点击 "Open View" 按钮
7. 在打开的对话框中：
   - 检查 "Run Details" 标签页，确认显示的是第二个项的运行日志（不是第一个项的）
   - 切换到 "Workspace" 标签页，确认显示的是第二个项的转录内容（不是第一个项的）
   - **关键验证点**：转录片段应该与第二个项匹配，而不是第一个项的内容

### 测试场景 2：从运行中的项切换到已完成的项
1. 添加一个新任务到队列
2. 启动队列处理
3. 当任务正在运行时，勾选该项并点击 "Open View"
4. 确认 "Run Details" 显示实时进度
5. 确认 "Workspace" 标签页显示实时转录片段（如果启用了渐进式转录）
6. 关闭对话框
7. 等待任务完成
8. 取消勾选该项，勾选另一个已完成的项
9. 点击 "Open View"
10. **关键验证点**：
    - "Run Details" 应该显示新选择项的日志，而不是之前运行项的日志
    - "Workspace" 应该显示新选择项的完整转录，而不是之前项的内容

### 测试场景 3：媒体播放器状态隔离
1. 打开第一个已完成项的 View
2. 在 "Workspace" 中绑定媒体文件并播放
3. 关闭对话框
4. 打开第二个已完成项的 View
5. **关键验证点**：
    - 媒体播放器应该显示 "Binding: Unbound"
    - 媒体播放器应该是停止状态
    - 不应该继续播放第一个项的媒体

### 预期结果
- 每次打开不同的 QueueItem 时，对话框应该完全清除之前的内容
- Run Details 和 Workspace 都应该显示当前选择项的内容
- 媒体播放器状态应该被重置
- 不应该出现内容混淆或状态残留

### 如果测试失败
如果在测试中发现 Workspace 仍然显示上一个项的内容：
1. 检查控制台是否有错误信息
2. 确认 `clear_content()` 方法是否被正确调用
3. 检查是否有异常导致 `_load_transcript()` 没有执行
4. 提交 bug 报告，包含详细的复现步骤和截图
